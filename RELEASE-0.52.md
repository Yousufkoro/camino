# 0.52 — Consolidate coverage and scope past/future advice

A production sample had no screened proposed revisions but still displayed generic add-more advice in a separate prompt-observations section. Consolidate visible coverage into the checked requirement-by-requirement review, and proposed changes into the screened revision list. Omit the redundant observation section for both fresh and legacy saved reviews. Neutralize its feedback/actions in new API responses while preserving the legacy field and evidence metadata for compatibility. Downloaded visible feedback follows the same presentation.

The secondary checker now links proposed revisions to a numbered source requirement (or -1 for general writing advice). Scope the observed-result guard to that requirement. Preserve expected-outcome advice for explicitly future requirements. When a mixed past/future suggestion cannot be tied to a requirement, or its requirement itself combines both, flag the result-related advice as uncertain rather than replacing a legitimate goal with a demand for an observed result. Single observed-result prompts retain the prior truthful-outcome guard.

Regression tests exercise past/future links, unknown and combined scopes, propagation through the checker, neutralized API observations, and fresh/saved rendering. The explicitly gated synthetic probe now includes mixed-outcomes. Full validation precedes deployment; live model samples and browser replay remain separate evidence. Reviewer keeps(Beta); broader model quality and device gates remain open. Separate passes with the same model are not independent validation.
